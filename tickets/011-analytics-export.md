# Ticket 011 — Аналитика и обезличенные выгрузки

Зависит от Ticket 010. Перед выполнением прочитать `tickets/README.md` и `tickets/progress.md`.

## Цель

Построить дашборд и CSV/XLSX только по безопасным метаданным, используя Kafka-события без текстов обращения.

## Checkpoints

1. Transactional outbox и публикация безопасных событий в Kafka.
2. Worker и аналитическая проекция в PostgreSQL.
3. Дашборд с метриками из ТЗ.
4. CSV/XLSX по whitelist и Docker smoke C8.

## План

- Добавить EF Core outbox: изменение тикета и запись события фиксируются одной транзакцией.
- Worker публикует события в Kafka идемпотентно; consumer строит read model с защитой от повторной доставки.
- Event schema содержит только ids, тип заявителя, категорию, статус, приоритет, timestamps, assignment ids и счетчики. Тексты, заметки, контакты, имена файлов и трек-номер запрещены schema test.
- Реализовать метрики: количество за период, распределения, среднее время до принятия оператором/первого ответа/закрытия, нагрузка, доля срочных, доля возвратов.
- Зафиксировать определения метрик в README/API schema. Ожидание заявителя включать в календарное время для MVP; обе даты сохранять для будущего изменения формулы.
- Оператор и эксперт видят только показатели по себе; администратор — общие.
- Создать экспорт по явному whitelist. Для XLSX использовать свободно лицензируемую библиотеку, например ClosedXML, после фиксации ее версии и лицензии.
- Не включать трек-номер, свободные ответы, chat, notes, attachments, contacts, IP/User-Agent.
- Аудировать создание и скачивание экспорта; временный файл удалять после выдачи.

## Проверки

- Полный C8.
- Повторная доставка Kafka event не удваивает метрику.
- Сверка read model с контрольными тикетами дает ожидаемые значения.
- Schema/contract test падает при появлении запрещенного поля.
- Поиск фрагментов исходного текста и трек-номеров в CSV/XLSX ничего не находит.
- Роль видит только разрешенный срез.

## Docker checkpoint

Seed создает известный набор тикетов. Пользователь открывает дашборд, сверяет контрольные числа, скачивает CSV и XLSX и проверяет отсутствие текстов. URL и результаты записать в `progress.md`.

## Готово, когда

C8 проходит, Kafka реально участвует в построении проекции, доставка идемпотентна, а whitelist экспорта подтвержден автоматическими тестами.
