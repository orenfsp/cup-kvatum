# Ticket 002 — Аутентификация сотрудников и роли

Зависит от Ticket 001. Перед выполнением прочитать `tickets/README.md` и `tickets/progress.md`.

## Цель

Реализовать безопасный вход сотрудников и серверное разграничение ролей `Operator`, `Expert`, `Administrator` с видимыми кабинетами-заглушками.

## Checkpoints

1. Модель пользователей, ролей и детерминированные тестовые учетные записи.
2. Вход/выход через HttpOnly cookie и защищенные staff routes.
3. Три разных mobile/desktop кабинета с навигацией Material Web.
4. Интеграционные тесты матрицы доступа и Docker smoke.

## План

- Настроить ASP.NET Core Identity, EF Core migrations и роли.
- Создать test-only seed оператора, эксперта и администратора; пароли передавать через dev environment и документировать в README.
- Реализовать `/api/staff/auth/login`, `/logout`, `/me`; ограничить cookie `HttpOnly`, `SameSite`, срок жизни и CSRF-защиту. В Docker Development разрешить локальный HTTP, production-конфигурацию оставить secure-only.
- Сделать server-side policies по ролям; скрытие кнопки на frontend не считается защитой.
- В React добавить login, guards и layouts ролей. TanStack Query хранит server state, Zustand — только UI state.
- Добавить обработку истечения сессии без бесконечных Axios retry.
- Зафиксировать события входа/выхода и неуспешного входа без паролей и cookie в логах.

## Проверки

- Каждая роль входит в свой кабинет.
- Попытка открыть API чужой роли возвращает 403.
- Неавторизованный staff endpoint возвращает 401.
- Logout инвалидирует сессию.
- Логи не содержат паролей и cookie.

## Docker checkpoint

После `docker compose up --build -d` пользователь входит тремя тестовыми учетными записями и видит отдельные кабинеты «Оператор», «Эксперт», «Администратор». URL и логины записать в `progress.md`.

## Готово, когда

Роли защищены на backend, все проверки проходят в контейнерах, кабинеты доступны локально, а тестовые учетные записи описаны в README.
