# Ticket 010 — Администрирование, учетные записи и журнал

Зависит от Ticket 009. Перед выполнением прочитать `tickets/README.md` и `tickets/progress.md`.

## Цель

Дать администратору управление категориями, правилами маршрутизации, лимитами и сотрудниками без доступа к содержимому обращений.

## Checkpoints

1. CRUD категорий, групп и правил с валидацией.
2. Управление учетными записями, ролями и доступностью экспертов.
3. Служебный список зависших обращений и безопасное разблокирование.
4. Полный audit trail и Docker smoke C7.

## План

- Реализовать категории с активностью и порядком отображения. Использованную категорию деактивировать, а не физически удалять.
- Реализовать группы экспертов, membership, лимит нагрузки и правило `категория → группа`.
- Сохранять версию правила, использованную при подсказке, чтобы изменение конфигурации не переписывало историю.
- Добавить создание, блокировку и восстановление staff account; выдачу ровно одной рабочей роли в MVP.
- Добавить состояние эксперта `Available/Unavailable`; недоступный эксперт не предлагается для новых назначений.
- Показать администратору только ticket id, категорию, статус, приоритет, назначение и timestamps. Не загружать тексты, вложения, чат, заметки и кризисный контакт.
- Разрешить изменение статуса, приоритета и исполнителя зависшего тикета только с обязательной причиной.
- Аудировать actor, action, target id, timestamp, before/after безопасных метаданных и причину; тексты обращений в audit не копировать.
- Дать admin UI фильтры журнала и read-only просмотр деталей события.

## Проверки

- Полный C7.
- Новая категория появляется в форме заявителя и влияет на подсказку.
- Деактивированная категория остается у старого тикета, но недоступна для нового.
- Заблокированный сотрудник теряет сессию и не входит снова.
- Admin API никогда не возвращает запрещенное содержимое.
- Изменение зависшего тикета без причины отклоняется.

## Docker checkpoint

Администратор создает категорию и правило, создает эксперта, затем тестовое обращение получает правильную подсказку. После административного изменения в журнале появляется запись. URL и учетные данные записать в `progress.md`.

## Готово, когда

C7 проходит, конфигурация влияет на реальную маршрутизацию, аудит полон, а администратор технически изолирован от содержимого обращений.
