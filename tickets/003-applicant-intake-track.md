# Ticket 003 — Подача обращения, статусы и трек-номер

Зависит от Ticket 002. Перед выполнением прочитать `tickets/README.md` и `tickets/progress.md`.

## Цель

Дать анонимному заявителю полный первый сквозной путь: выбрать тип и способ подачи, отправить обращение, получить трек-номер и открыть статус без регистрации.

## Checkpoints

1. Landing и выбор школьник/родитель/педагог с переключением «ты/вы».
2. Два равноправных пути подачи и необязательные уточняющие вопросы.
3. Создание обращения и криптографического трек-номера.
4. Страница сохранения номера и последующий просмотр статуса.

## План

- Создать доменные сущности обращения, категории, ответов на вопросы и истории статусов.
- Добавить начальные категории из ТЗ и 3–5 необязательных вопросов.
- Реализовать формы mobile-first на Material Web: свободный текст и категория, включая «Не знаю, как это назвать».
- Сформулировать бережные сообщения ошибок и успеха; обязательным оставить только рассказ/осмысленный выбор пути, не требовать ответы на уточнения.
- Создать публичный idempotent endpoint подачи с client request id.
- Генерировать `ОТК-XXXX-XXXX` из CSPRNG, исключить спорные символы, хранить нормализованный стойкий хеш и показывать секрет только при создании.
- Реализовать ввод номера, нормализацию дефисов/регистра, generic error и публичное чтение только своего обращения.
- Показать статусную линейку человеческими фразами; неоднозначное «Написать снова» заменяется контекстными действиями по правилам Ticket 015.
- Исключить трек-номер и текст обращения из логов.

## Проверки

- Приемочные сценарии C1 без вложения и C2.
- Пропуск уточняющих вопросов разрешен.
- Двойная отправка с одним request id создает один тикет и возвращает тот же результат.
- Неверный номер не раскрывает существование обращения.
- Заявитель не может открыть другое обращение без его секрета.
- Тон интерфейса меняется вместе с типом заявителя.

## Docker checkpoint

На локальном стенде пользователь создает два обращения: школьник свободным текстом и взрослый по категории. Сохраняет оба трек-номера и открывает страницы статуса. Демо-номера и URL записать в `progress.md`.

## Готово, когда

С1 без вложения и С2 проходят на мобильном viewport, обращение хранится в PostgreSQL, трек-номер защищает доступ, а весь стенд запускается общей Docker-командой.
