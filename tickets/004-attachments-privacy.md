# Ticket 004 — Вложения и очистка метаданных

Зависит от Ticket 003. Перед выполнением прочитать `tickets/README.md` и `tickets/progress.md`.

## Цель

Добавить к подаче обращения до пяти безопасно обработанных вложений без публичного доступа и без EXIF/геолокации.

## Checkpoints

1. Mobile upload с превью, прогрессом, удалением и восстановлением формы после ошибки.
2. Серверная валидация размера/типа и приватное файловое хранилище.
3. Перекодирование изображений, удаление метаданных и безопасная выдача.
4. Негативные тесты и Docker-демонстрация полного С1.

## План

- Разрешить PNG, JPEG и PDF; максимум пять файлов, до 10 МБ каждый.
- Проверять MIME по содержимому и отклонять активные/неподдерживаемые форматы.
- Для изображений выполнять decode/re-encode, удаляя EXIF, GPS и исходное имя.
- PDF хранить как приватное вложение после проверки структуры и отсутствия шифрования; отдавать только как attachment/без inline active content.
- Хранить байты в выделенном Docker volume через интерфейс storage service, метаданные и случайный storage key — в PostgreSQL.
- Не включать путь, исходное имя и содержимое в логи.
- Выдавать файл только после проверки права на конкретное обращение; публичных object URLs нет.
- При сбое отдельного файла сохранять введенный текст и позволять повторить загрузку.

## Проверки

- EXIF/GPS отсутствуют в сохраненном JPEG.
- Файл с подмененным расширением отклоняется.
- Шестой файл и файл больше лимита отклоняются бережным сообщением.
- Без трек-номера или staff permission скачать файл нельзя.
- Полный приемочный сценарий C1 проходит с вложением.

## Docker checkpoint

Создать обращение со скриншотом, открыть его по трек-номеру и скачать безопасную копию. В `progress.md` записать трек-номер, URL и результат проверки отсутствия метаданных.

## Готово, когда

Вложения работают в Docker, очищаются, не имеют публичных URL, проверки доступа и лимитов покрыты тестами, а С1 проходит полностью.
