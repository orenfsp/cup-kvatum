# Ticket 014 — Финальная приемка, демонстрационные данные и документация

Зависит от Ticket 013. Перед выполнением прочитать `tickets/README.md` и `tickets/progress.md`.

## Цель

Собрать воспроизводимый демонстрационный релиз и доказать прохождение всех восьми сценариев ТЗ из чистого Docker-запуска.

## Checkpoints

1. Детерминированный demo seed и сценарные данные.
2. Playwright/E2E для C1–C8 и ручной mobile QA.
3. Чистый Compose smoke, резервный reset/seed workflow и документация.
4. Финальный демонстрационный маршрут без скрытых шагов.

## План

- Создать demo seed с учетными записями всех ролей, категориями, группами, лимитами и наборами тикетов для каждого статуса.
- Добавить Playwright tests для C1–C8; загрузку файла, чат и role switching выполнять через UI, где это часть приемки.
- Добавить отдельные тесты mobile viewport и critical desktop staff screens.
- Проверить бережные тексты «ты/вы», отсутствие красных обвиняющих ошибок и понятные human statuses.
- Проверить keyboard navigation, labels, focus, contrast и основные screen-reader names.
- Выполнить чистую сборку Compose без host .NET/Node; миграции и seed должны выполняться предсказуемо и не гоняться параллельно.
- Добавить readiness wait и smoke script, который не использует фиксированные sleeps.
- Обновить корневой README: запуск одной командой, тестовые учетки, модель приватности, трек-номер, уведомления, кризисный сценарий, архитектура, тесты и список нереализованного.
- Явно указать в нереализованном: внешние интеграции, ML-классификация, production SLA/дежурство и реальная эксплуатационная аттестация.
- Проверить лицензии и сформировать короткий third-party notices список.
- Подготовить `DEMO.md`: последовательность кликов C1–C8, URL, учетки и ожидаемые результаты.

## Проверки

- C1–C8 проходят автоматически и вручную.
- Полная backend/frontend test suite green.
- Compose services healthy после чистой сборки.
- CSV/XLSX не содержат контрольный секретный текст.
- Матрица прав проходит negative suite.
- README-команды воспроизводятся буквально.
- После перезапуска данные и файлы сохраняются в volume; отдельный документированный demo reset возвращает seed.

## Docker checkpoint

На актуальном состоянии выполнить чистый `docker compose up --build -d`, дождаться health-checks без ручных исправлений и пройти маршрут из `DEMO.md`. В `progress.md` записать итоговые URL, учетки, команды, длительность сборки, результаты C1–C8 и ограничения.

## Готово, когда

Все восемь сценариев подтверждены, документация достаточна для запуска из чистого клона, итоговый стенд доступен локально, а `progress.md` содержит полный проверяемый handoff.
