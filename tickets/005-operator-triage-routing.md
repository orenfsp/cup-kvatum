# Ticket 005 — Очередь оператора и маршрутизация

Зависит от Ticket 004. Перед выполнением прочитать `tickets/README.md` и `tickets/progress.md`.

## Цель

Реализовать прием нового обращения оператором: очередь, категорию, приоритет, подсказку исполнителя, назначение и отклонение.

## Checkpoints

1. Очередь новых с сортировкой, ожиданием и счетчиком просроченных.
2. Карточка первичного обращения с ответами и вложениями.
3. Правила групп/нагрузки и подсказка назначения.
4. Назначение, операторский ответ и отклонение с Docker smoke C3.

## План

- Реализовать staff endpoints и UI очереди. Порядок: crisis flag, затем приоритет, затем старые раньше новых.
- Показать время ожидания и конфигурируемый порог просрочки; начальный demo-порог — четыре часа.
- В карточке показать только первоначальный текст, первичные ответы и первоначальные вложения. Чат и внутренние заметки не загружать даже скрытым frontend-запросом.
- Добавить словарную подсказку категории без автоматического изменения данных.
- Создать группы специалистов, membership, лимит активных обращений и правила `категория → группа`.
- Ранжировать допустимых экспертов по активной нагрузке; окончательный выбор делает оператор.
- Если эксперта нет, оставить обращение в очереди и создать admin alert.
- Если все достигли лимита, показать предупреждение; ручное превышение требует причины.
- Реализовать приоритеты `Urgent`, `Standard`, `Low`; система не может назначить `Urgent` автоматически.
- Реализовать назначение с атомарной сменой статуса на «Распределено».
- Реализовать отклонение `Spam` и `OutOfScope` с внутренней причиной и бережным сообщением заявителю.
- Реализовать простой ответ оператора без эксперта с завершением обращения и записью в историю.

## Проверки

- Полный C3.
- Два оператора не могут одновременно назначить разных экспертов без обнаружения конфликта версии.
- Операторский API не возвращает чат и заметки.
- Нет подходящего эксперта и перегрузка обрабатываются по ТЗ.
- Ручное превышение лимита и изменение приоритета журналируются.

## Docker checkpoint

Seed создает несколько новых обращений разного возраста и две группы экспертов. Пользователь входит оператором, сортирует очередь, назначает один тикет и отклоняет другой. URL и использованные id записать в `progress.md`.

## Готово, когда

C3 проходит, подсказка не заменяет человеческое решение, ограничения доступа соблюдены на API, а срез доступен в Docker.
