# Ticket 012 — PWA, безопасное возвращение и уведомления

Зависит от Ticket 011. Перед выполнением прочитать `tickets/README.md` и `tickets/progress.md`.

## Цель

Завершить mobile-first PWA: установка, возвращение к обращению на том же устройстве и нейтральные уведомления без привязки к личности.

## Checkpoints

1. Manifest, service worker и installable PWA shell.
2. Безопасная локальная сессия возврата без трек-номера в URL.
3. Web Push opt-in с нейтральным содержимым.
4. Offline/permission fallbacks и Docker-демонстрация.

## План

- Добавить manifest, иконки, theme colors, service worker и app-shell cache. Тексты обращений, чат, staff pages и API responses не кэшировать.
- После создания обращения устанавливать отдельную HttpOnly capability session для возврата на этом устройстве. Bookmark ведет на нейтральную status page; трек-номер не попадает в query/path.
- На новом устройстве сохраняется вход по трек-номеру.
- Реализовать явный opt-in push. Push subscription связывается только с appeal id, имеет revoke endpoint и описанное снижение приватности.
- Уведомление содержит только «В обращении есть обновление» и открывает нейтральную status page.
- Не отправлять notification payload с текстом, категорией, приоритетом, ролью эксперта или трек-номером.
- Обработать отказ в permission, неподдерживаемый browser и отключенный service worker: основной сценарий по трек-номеру продолжает работать.
- Добавить кнопку удаления локальной сессии/отписки на общем устройстве.
- Проверить mobile layout, экранную клавиатуру, safe-area и доступность основных controls.

## Проверки

- Lighthouse/браузер признает приложение installable на localhost.
- Reload/offline показывает только shell и не показывает ранее открытый чувствительный текст.
- Bookmark не содержит секрета.
- Push payload нейтрален; revoke прекращает уведомления.
- Отказ в push не блокирует ни один сценарий.
- После удаления локальной сессии для обращения снова нужен трек-номер.

## Docker checkpoint

Установить PWA локально, создать обращение, вернуться по сохраненной странице, показать нейтральное тестовое уведомление и удалить локальную сессию. Инструкцию воспроизведения записать в `progress.md`.

## Готово, когда

PWA устанавливается, чувствительные данные не кэшируются, возвращение и push не раскрывают трек-номер, а все fallbacks работают в Docker.
