# Демо и приемка C1–C8

## Подготовка

Запустите стенд и дождитесь сообщения `Demo is ready`:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-demo.ps1
```

Основной URL — <http://localhost:3000>. Для чистого повторения всех шагов выполните осознанный reset:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/reset-demo.ps1 -ConfirmDataLoss
```

Учетки: `operator / Operator!2026`, `expert / ExpertHelp!2026`, `expert.mediator / ExpertHelp!2026`, `administrator / AdminPanel!2026`.

## C1 — школьник, свободный рассказ и файл

1. На `/appeal/new` выбрать «Школьник» → «Рассказать своими словами».
2. Написать не меньше 10 знаков, частично заполнить необязательные ответы, приложить PNG/JPEG/PDF.
3. Отправить и убедиться, что появился трек-номер, кнопки «Скопировать номер» и «Сохранить в файл».
4. Ожидаемо: обращение принято без имени/регистрации; файл помечен безопасно загруженным; повторный submit не создает дубликат.

## C2 — взрослый и категории

1. Создать второе обращение как «Родитель» или «Педагог».
2. Убедиться в обращении на «вы», выбрать «Выбрать категорию».
3. Проверить обычную категорию и отдельно «Не знаю, как это назвать»: для нее доступен свободный текст.
4. Ожидаемо: обращение с треком появляется в первичной очереди.

## C3 — оператор

1. Войти оператором на `/staff`; открыть очередь и `ОТК-TRST-2345` (первая школьная карточка после чистого seed).
2. Проверить прозрачную подсказку категории, подтвердить либо изменить категорию/приоритет, сохранить разбор.
3. Выбрать специалиста и назначить; ожидаемый статус — «Назначено специалисту».
4. Открыть `ОТК-CARE-6789`, вкладку «Отклонить», выбрать «Спам», указать внутреннюю причину и подтвердить.
5. Ожидаемо: обе карточки исчезли из первичной очереди; в операторской карточке никогда нет экспертных заметок.

## C4 — эксперт, диалог и совместная работа

1. Войти экспертом, открыть `ОТК-ASGN-3456`, нажать «Взять в работу».
2. Добавить внутреннюю заметку и убедиться, что она видна только в экспертном кабинете.
3. Задать вопрос заявителю; по `ОТК-ASGN-3456` на `/appeal/status` ответить в анонимном диалоге.
4. В экспертной карточке запросить соисполнителя или передачу. Войти оператором → «Запросы», открыть запрос и подтвердить профильного специалиста.
5. Вернуться ответственным экспертом и опубликовать рекомендацию.
6. Ожидаемо: вопрос дает «Нужно уточнение», ответ возвращает «В работе», публикация дает «Подготовлена рекомендация»; заявитель не видит имя и внутреннюю заметку.

## C5 — «это не помогло» и возврат

1. На `/appeal/status` открыть `ОТК-RSPN-6789`, нажать «Это не помогло», выбрать причину и отправить.
2. Войти оператором → «Возвраты», выбрать карточку и назначить специалиста повторно либо завершить бережным объяснением.
3. При повторном назначении эксперт принимает карточку и публикует новую версию рекомендации.
4. Заявитель нажимает «Это помогло» и оставляет оценку.
5. Ожидаемо: история сохраняет возврат и версии ответа; после подтверждения статус «Закрыто», доступна оценка.

## C6 — непосредственная опасность без личности и контакта

1. Открыть `ОТК-RUSH-DEFG` или создать обращение с фразой о непосредственной угрозе.
2. Ожидаемо сразу, еще до отправки: видны `112`, `8-800-2000-122`, `124`; контакт добровольный, отправка без него разрешена.
3. Войти оператором → «Срочная помощь». Кризисная карточка находится наверху, показывает ожидание и отсутствие контакта.
4. Нажать «Подтвердить срочность», затем открыть ее в основной очереди и назначить специалиста.
5. Ожидаемо: система не деанонимизирует человека и не обещает исходящий вызов; помощь продолжается через экстренные номера и анонимный чат, авто-закрытие запрещено.

## C7 — администратор

1. Войти администратором. В «Конфигурации» создать категорию, группу с экспертом и лимитом, затем связать их правилом.
2. В «Сотрудниках» создать тестовую учетку с одной ролью, при необходимости заблокировать и восстановить ее.
3. В «Зависших» выбрать `ОТК-RTRN-789A`, изменить безопасные служебные поля и обязательно указать причину.
4. В «Журнале» проверить запись со значениями до/после.
5. Ожидаемо: интерфейс показывает границу доступа; текст, чат, заметки, файлы, контакты и треки отсутствуют.

## C8 — аналитика и выгрузки

1. Открыть «Аналитика», сменить период между 7/30/90/365 днями.
2. Скачать CSV и XLSX.
3. Ожидаемо: дашборд показывает агрегаты и нагрузку; выгрузки содержат только whitelist полей и удаляются после первой выдачи.

## Автоматическое подтверждение

```powershell
docker compose -p otklik --profile tests run --rm --build integration-tests
docker compose -p otklik --profile tests run --rm --build e2e-tests
```

Backend suite проходит C1–C8, идемпотентность, negative RBAC/CSRF/object access и проверку полей CSV/XLSX. Playwright повторяет критический путь в UI на mobile и desktop, включая файл, чат, role switching, admin changes и downloads.
