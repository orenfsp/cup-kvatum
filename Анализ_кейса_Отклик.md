# «Отклик»: уточненный анализ MVP строго по ТЗ

## 1. Зафиксированные границы

Делаем только MVP, описанный в ТЗ.

- Внешних интеграций и автоматической передачи обращений государственным органам в MVP нет.
- Типы заявителя только из ТЗ: школьник, родитель, педагог.
- Дополнительных возрастных диапазонов нет. Выбор «школьник» включает бережный интерфейс на «ты», выбор «родитель» или «педагог» — интерфейс на «вы».
- Для всех заявителей остаются два равноправных пути из ТЗ: выбрать категорию или описать ситуацию своими словами.
- Роли только из ТЗ: заявитель, оператор, эксперт, администратор.
- Пользовательские сценарии только восемь приемочных сценариев из ТЗ.
- Автоматическая классификация может быть реализована простыми правилами и словарем. Решение о категории, приоритете и исполнителе принимает оператор.
- Telegram-бот не используется. Основной вариант — адаптивное mobile-first веб-приложение/PWA.

## 2. Состав MVP

### Заявитель

- первый экран с объяснением сервиса, анонимности и дальнейших шагов;
- выбор: школьник, родитель или педагог;
- подача по категории либо свободным текстом;
- обязательная категория «Не знаю, как это назвать», ведущая к свободному описанию;
- 3–5 необязательных уточняющих вопросов;
- до пяти вложений с серверным удалением EXIF и геометок;
- получение и сохранение трек-номера;
- просмотр статуса и чата по трек-номеру;
- возможность дополнять обращение и отвечать эксперту;
- просмотр рекомендаций;
- действия «Это помогло» и «Это не помогло»;
- оценка работы и отдельная жалоба на специалиста.

### Оператор

- очередь новых обращений: кризисные сверху, затем старые раньше новых;
- время ожидания и счетчик просроченных;
- просмотр первоначального обращения, ответов, вложений и подсказки категории;
- изменение категории и приоритета;
- назначение эксперта;
- отклонение спама и обращений вне компетенции с причиной;
- самостоятельный ответ, когда эксперт не нужен;
- контроль распределенных и зависших обращений без доступа к чату заявителя с экспертом;
- обработка запросов на передачу, соисполнителя и пересмотр приоритета;
- обработка возвращенных обращений.

### Эксперт

- только назначенные обращения;
- фильтры по статусу, приоритету и категории;
- чат с заявителем;
- внутренние заметки;
- изменение рабочего статуса;
- итоговые рекомендации;
- запрос передачи другому эксперту;
- запрос соисполнителя;
- запрос пересмотра приоритета у оператора.

### Администратор

- категории;
- соответствие категорий группам экспертов;
- лимиты активных обращений;
- учетные записи и права;
- изменение статуса, приоритета и исполнителя зависшего обращения с обязательной причиной;
- журнал действий;
- аналитика и обезличенные выгрузки.

Администратор не читает обращения, вложения, чат и внутренние заметки и не закрывает обращения.

## 3. Модель доступа

| Данные или действие | Заявитель | Оператор | Эксперт | Администратор |
|---|---:|---:|---:|---:|
| Создать обращение | свое | нет | нет | нет |
| Читать первоначальное обращение | свое | да | назначенные | нет |
| Читать чат | свой | нет | назначенные | нет |
| Читать вложения | свои | первоначальные | назначенные | нет |
| Категория и приоритет | видеть | менять | видеть | менять для разблокировки |
| Назначение эксперта | видеть без имени | менять | видеть участников | менять для разблокировки |
| Рабочий статус | частично | менять | менять | менять для разблокировки |
| Внутренние заметки | нет | нет | участники обращения | нет |
| Контакт при кризисе | свой | только кризисный и только при наличии | нет | нет |
| Аналитика | нет | по себе | по себе | вся обезличенная |

При конфликте формулировок применяется матрица прав: оператор не видит внутренние заметки. Для передачи, подключения соисполнителя и пересмотра приоритета используются отдельные структурированные запросы без раскрытия заметок и чата.

## 4. Сценарии из ТЗ

### С1. Свободный рассказ школьника

1. Пользователь открывает первый экран.
2. Выбирает «Школьник»; интерфейс переходит на «ты».
3. Выбирает «Рассказать своими словами».
4. Пишет текст.
5. Отвечает на часть необязательных вопросов.
6. При желании добавляет вложение.
7. Отправляет обращение.
8. Получает трек-номер с кнопками копирования и сохранения.

### С2. Обращение взрослого по категории

1. Пользователь выбирает «Родитель» или «Педагог»; интерфейс переходит на «вы».
2. Выбирает категорию.
3. Может выбрать «Не знаю, как это назвать» и перейти к свободному тексту.
4. Отправляет обращение в очередь оператора.

### С3. Работа оператора

1. Оператор авторизуется.
2. Видит очередь и открывает новое обращение.
3. Видит подсказку категории.
4. Подтверждает или меняет категорию.
5. Выставляет приоритет.
6. Назначает эксперта; статус становится «Распределено».
7. Другое обращение может отклонить как спам с причиной.

### С4. Работа эксперта

1. Эксперт видит только свои обращения.
2. Переводит назначенное обращение в «В работе».
3. Задает вопрос; статус становится «Нужно уточнение».
4. Оставляет внутреннюю заметку, не видимую заявителю.
5. Запрашивает передачу или соисполнителя; оператор подтверждает.
6. Публикует рекомендации; статус становится «Ответ готов».

### С5. «Это не помогло»

1. Заявитель входит по трек-номеру и отвечает на вопрос эксперта.
2. После рекомендаций выбирает «Это не помогло» и указывает причину.
3. Обращение получает статус «Возвращено» и попадает оператору.
4. Оператор назначает того же или другого эксперта либо закрывает с объяснением.
5. После нового ответа заявитель подтверждает результат и оценивает работу.

### С6. Кризисное обращение

1. Словарь кризисных маркеров находит риск в тексте или ответах.
2. Пользователь немедленно видит контакты помощи; форма не блокируется.
3. Пользователь может добровольно оставить способ связи или отказаться.
4. Обращение попадает в отдельный блок сверху очереди оператора с таймером.
5. Оператор вручную выставляет «Срочно» и назначает специалиста.

### С7. Администрирование

1. Администратор добавляет категорию.
2. Связывает ее с группой экспертов и лимитом нагрузки.
3. Создает учетные записи и выдает роли.
4. Проверяет работу правила на тестовом обращении.
5. Разблокирует зависшее обращение с причиной; действие попадает в журнал.

### С8. Аналитика

1. Администратор выбирает период и видит метрики из ТЗ.
2. Выгружает CSV/XLSX.
3. В выгрузке отсутствуют тексты, чат, вложения, контакты и трек-номера.

## 5. Статусы и переходы

| Текущий статус | Действие | Новый статус | Кто выполняет |
|---|---|---|---|
| — | обращение отправлено | Новое | система |
| Новое | эксперт назначен | Распределено | оператор |
| Распределено | обращение принято | В работе | эксперт |
| В работе | задан вопрос | Нужно уточнение | эксперт |
| Нужно уточнение | заявитель ответил | В работе | система |
| В работе | опубликованы рекомендации | Ответ готов | эксперт |
| Ответ готов | «Это помогло» | Завершено | заявитель |
| Ответ готов | «Это не помогло» | Возвращено | заявитель |
| Возвращено | назначен эксперт | Распределено | оператор |
| Новое | спам или вне компетенции | Отклонено | оператор |
| Нужно уточнение / Ответ готов | заявитель не вернулся N дней | Закрыто без ответа | система |

Практические решения команды:

- после ответа заявителя статус автоматически возвращается в «В работе»;
- повторное назначение из «Возвращено» переводит в «Распределено»;
- операторский ответ без эксперта отображается заявителю как итоговый ответ сервиса, после чего обращение завершается оператором;
- после закрытия пользователь явно выбирает: продолжить ту же ситуацию с сохранением общего трека и истории либо создать отдельное обращение с новым треком; неоднозначное «Написать снова» не используется;
- число возвратов — два, как рекомендовано в ТЗ; после второго возврата оператор принимает окончательное решение с объяснением.

## 6. Маршрутизация

1. Система получает роль заявителя, категорию, ответы на вопросы и результат проверки кризисных маркеров.
2. Если выбран свободный текст, словарь ключевых слов предлагает категорию.
3. Правила администратора возвращают допустимую группу экспертов.
4. Эксперты сортируются по числу активных обращений.
5. Оператор видит рекомендацию и принимает окончательное решение.
6. Если подходящего эксперта нет, обращение остается у оператора и подсвечивается администратору.
7. Если все эксперты достигли лимита, обращение остается в очереди; оператор получает предупреждение и может осознанно назначить его вручную.

Приоритет система не выставляет. Кризисный флаг только поднимает обращение наверх и требует внимания оператора.

## 7. Решение кризисного случая без способа связи

Если заявитель сообщает о непосредственной опасности, но остается анонимным и не оставляет контакт, система не может сама найти человека или вызвать помощь по его адресу. Попытка скрытой деанонимизации прямо противоречила бы ТЗ. Поэтому MVP действует следующим образом.

### Немедленно на стороне заявителя

1. Показывает заметный, спокойный блок: «Если опасность прямо сейчас, позвони в экстренную службу».
2. Дает одну крупную кнопку звонка и утвержденный организаторами список кризисных контактов.
3. Не перекрывает и не сбрасывает введенный рассказ.
4. Предлагает простые действия безопасности: перейти туда, где есть другие люди; обратиться к взрослому, которому пользователь доверяет; не оставаться одному; покинуть опасное место, если это можно сделать безопасно.
5. Предлагает добровольно оставить способ связи и понятным языком объясняет, что его увидит только кризисный оператор.
6. Если контакт не оставлен, предлагает сохранить страницу/трек-номер и не закрывать ее, чтобы увидеть ответ специалиста.

### На стороне платформы

1. Обращение автоматически получает кризисный флаг, но не приоритет «Срочно» — его подтверждает оператор.
2. Оно размещается в отдельном верхнем блоке очереди с таймером ожидания.
3. Оператор берет его вне очереди и назначает специалиста.
4. Специалист немедленно пишет в анонимный чат и уточняет, находится ли заявитель сейчас в безопасности.
5. При отказе оставить контакт помощь продолжается в чате; отказ не ухудшает приоритет и не блокирует обращение.
6. Система не использует IP, User-Agent или другие технические данные для установления личности и ничего автоматически не передает наружу.

### Честное ограничение

Интерфейс должен прямо, но бережно объяснить: без способа связи и сведений о местонахождении сервис способен дать инструкции и отвечать в чате, но не способен самостоятельно направить помощь к человеку. Это не ошибка процесса, а следствие выбранной пользователем анонимности.

## 8. Трек-номер и возвращение

- формат `ОТК-XXXX-XXXX`;
- символы без `0/O`, `1/I/l`;
- генерация криптографически стойким источником случайности;
- хранение в базе в виде хеша;
- одинаковое сообщение для неверного и несуществующего номера;
- не более пяти неуспешных проверок в минуту с одного адреса, затем задержка;
- IP используется только во временном счетчике ограничения и не связывается с обращением;
- кнопки «Скопировать» и «Сохранить»;
- безопасная закладка/PWA-сессия для возврата на том же устройстве;
- предупреждение, что восстановить номер на другом устройстве невозможно;
- потеря номера не приводит к поиску обращения по имени, телефону или содержанию.

## 9. Уведомления

Для MVP:

- основной механизм — самостоятельный возврат по трек-номеру или сохраненной странице;
- дополнительный — PWA push без привязки к личности;
- текст push нейтральный: «В обращении есть обновление»;
- текст обращения, категория и имя специалиста в уведомление не попадают;
- телефон и почта не запрашиваются в обычном сценарии;
- способ связи предлагается отдельно только при кризисном флаге и хранится отдельно.

## 10. Вложения

Решение для MVP:

- максимум пять файлов;
- максимум 10 МБ на файл;
- разрешены PNG, JPEG и PDF;
- проверяется фактический MIME-тип, а не только расширение;
- изображения перекодируются на сервере, EXIF и геометки удаляются;
- исходное имя файла не показывается другим пользователям;
- активные форматы вроде SVG и HTML запрещены;
- при ошибке одного файла остальные и текст обращения не теряются;
- вложения доступны только оператору до назначения и участникам обращения после назначения.

## 11. Аналитика

Метрики строго из ТЗ:

- количество обращений за период;
- распределение по категориям, типам заявителей и статусам;
- среднее время до принятия оператором;
- среднее время до первого ответа;
- среднее время до закрытия;
- нагрузка по операторам и экспертам;
- доля срочных;
- доля возвратов.

В CSV/XLSX включаются только: дата создания с точностью до дня, категория, тип заявителя, статус, приоритет, временные интервалы, количество передач/возвратов и обезличенные идентификаторы сотрудников для расчета нагрузки.

Не включаются: трек-номер, текст обращения, ответы на вопросы в свободной форме, сообщения, заметки, вложения, контакты и технические данные пользователя.

## 12. Корнер-кейсы в рамках ТЗ

- Двойное нажатие «Отправить» не создает два обращения.
- Если ответ сервера потерян после отправки, повтор запроса возвращает тот же результат.
- Неверный трек-номер не раскрывает, существует ли похожий номер.
- Потерянный трек-номер нельзя восстановить; пользователь может создать новое обращение.
- Пропуск всех необязательных вопросов не блокирует отправку.
- «Не знаю, как это назвать» всегда ведет к свободному тексту.
- Ошибка загрузки вложения не удаляет введенный текст.
- Кризисный маркер не блокирует форму и не ставит приоритет автоматически.
- Если подходящего эксперта нет, обращение остается у оператора и подсвечивается администратору.
- Если эксперты перегружены, система не назначает исполнителя молча.
- Одновременная отправка сообщений двумя экспертами предотвращается блокировкой поля или серверной проверкой.
- При передаче обращения старый эксперт теряет право отправлять новые сообщения.
- Соисполнитель после удаления сразу теряет доступ.
- Новое сообщение заявителя из статуса «Нужно уточнение» возвращает обращение в работу.
- «Это не помогло» всегда отправляет обращение оператору, а не прежнему эксперту.
- Две одновременные попытки завершить и вернуть обращение обрабатываются как одна атомарная операция.
- Жалоба на специалиста не показывается этому специалисту.
- Кризисное обращение не закрывается автоматически без ответа по обычному таймеру; сначала требуется ручная проверка оператором.
- В выгрузку не попадают тексты даже при применении любых фильтров.
- Администраторское изменение зависшего обращения невозможно без причины и записи в журнале.

## 13. Закрытые решения заказчика

1. Оператор не видит внутренние заметки; приоритет имеет матрица прав.
2. Полный перечень кризисных контактов не задан и отдельно не оценивается. В MVP обязательно указываются детский телефон доверия `8-800-2000-122` и короткий номер `124` для мобильных; значения остаются конфигурируемыми.
3. Отдельные критерии оценки не входят в планирование проекта.
4. Внешние интеграции и передача обращений во внешние сервисы в MVP не реализуются.

Открытых вопросов, блокирующих составление и выполнение плана, нет.

## 14. Готовность MVP

MVP готов, когда восемь приемочных сценариев проходят на мобильном экране; роли не получают запрещенные данные; кризисный сценарий показывает немедленную помощь и поднимает обращение в очередь; трек-номер защищен от перебора; вложения очищаются; возврат идет оператору; журнал фиксирует административные изменения; выгрузка не содержит текстов и контактов; проект запускается одной командой из чистого клона.
