# Отклик

«Отклик» — mobile-first PWA для анонимных обращений о травле, конфликте и давлении. Заявитель не регистрируется и возвращается по секретному трек-номеру либо через защищенный доступ текущего устройства. Оператор маршрутизирует обращение, эксперт ведет анонимный диалог и готовит рекомендации, администратор работает только с конфигурацией и обезличенными данными.

## Запуск одной командой

Нужен только Docker Desktop или Docker Engine с Compose v2. Локальные .NET SDK и Node.js не требуются.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-demo.ps1
```

При первом запуске скрипт создает игнорируемый `.env` с локальными случайными секретами, собирает контейнеры и ждет реальной readiness-проверки. После запуска:

- приложение: <http://localhost:3000>
- подача обращения: <http://localhost:3000/appeal/new>
- моё обращение: <http://localhost:3000/appeal>
- кабинет: <http://localhost:3000/staff>
- техническое состояние: <http://localhost:3000/system>
- API readiness: <http://localhost:8080/api/health/ready>

Если `.env` уже создан из `.env.example`, в нем не должно оставаться значений в угловых скобках. Порты можно переопределить параметрами `-FrontendPort` и `-ApiPort`.

## Приватность и границы ролей

Трек-номер — секрет доступа. Он передается только в теле POST, не попадает в URL, аналитику, push payload, логи или offline-кэш. На текущем устройстве сервер может сохранить отдельную HttpOnly capability; ее можно отозвать кнопкой «Удалить доступ с устройства».

Оператор видит первоначальное обращение и его вложения для разбора, но не видит экспертный чат и внутренние заметки. В разделе «Линия» он выбирает срочный, обычный или низкий приоритет и получает по одной атомарно закреплённой карточке без общего списка; после завершения автоматически открывается следующая. Эксперт видит содержание только назначенного ему обращения либо обращения, где он активный соисполнитель. Его навигация показывает живые счётчики новых, активных, ожидающих и завершённых обращений; ответ заявителя без перезагрузки возвращает карточку в «В работе». Администратор не получает тексты, ответы, чат, заметки, файлы, кризисные контакты и трек-номера. CSV/XLSX строятся по фиксированному whitelist обезличенных служебных полей.

Файлы хранятся приватно. Принимаются до пяти PNG, JPEG или PDF размером до 10 МБ; MIME проверяется по сигнатуре, изображения перекодируются без EXIF/GPS, активные и зашифрованные PDF отклоняются.

## Кризисный сценарий

Если текст указывает на непосредственную опасность, форма сразу показывает `112`, детский телефон доверия `8-800-2000-122` и короткий номер `124`. Подача не блокируется. Контакт можно оставить добровольно; он хранится отдельно в зашифрованном виде и открывается только оператором с аудитом.

Если контакта нет, система не пытается установить личность и не обещает невозможный исходящий вызов. Обращение поднимается в кризисную очередь с таймером, источником сигнала и исходными сведениями. Оператор подтверждает срочность и назначает специалиста либо снимает ошибочный сигнал с обязательной причиной. Экспертный диалог оператору не раскрывается; кризисное обращение не закрывается автоматически.

## Архитектура

React PWA использует Axios, TanStack Query, Zustand и Material Web; дизайн-фундамент и ограничения интерфейса зафиксированы в [DESIGN_SYSTEM.md](./src/frontend/DESIGN_SYSTEM.md). Nginx раздает статические файлы и проксирует same-origin API.

ASP.NET Core API реализует Identity cookie, CSRF, RBAC, публичную подачу, очереди и выгрузки. PostgreSQL хранит рабочую модель и transactional outbox. Worker публикует обезличенные события в Kafka, обновляет отдельную аналитическую проекцию и обрабатывает авто-закрытие/нейтральные push-уведомления. Redis используется для rate limit, idempotency, lease совместного редактора и атомарного закрепления операторских задач. Файлы и Data Protection keys вынесены в отдельные Docker volumes.

## Проверки

Быстрый smoke уже запущенного стенда:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify-demo.ps1
```

Полный container-only набор:

```powershell
docker build --target test -f src/backend/Otklik.Api/Dockerfile .
docker build --target test -f src/frontend/Dockerfile .
docker compose -p otklik --profile tests run --rm --build integration-tests
docker compose -p otklik --profile tests run --rm --build e2e-tests
```

Playwright проверяет mobile и desktop, Material/Onest-фундамент, маршруты и историю браузера, подачу с файлом, обращение школьника и взрослого, операторский разбор, экспертные диалог/заметки/ответ/команду, возврат, кризисную очередь, административный list-detail и выгрузки. Дополнительно проверяются клавиатурный доступ, имена контролов, фокус, отсутствие горизонтальной прокрутки, градиентов, декоративных буллетов, статусных капсул и обязательных tooltip. Backend negative suite проверяет CSRF, роли, object-level access, конкурентное продолжение одной истории и отсутствие закрытых полей в аналитике.

Проверка зависимостей:

```powershell
dotnet list Otklik.slnx package --vulnerable --include-transitive
Set-Location src/frontend
npm audit
npm audit --omit=dev
```

Отчет о защитных мерах находится в [SECURITY_REVIEW.md](./SECURITY_REVIEW.md), лицензии — в [THIRD_PARTY_NOTICES.md](./THIRD_PARTY_NOTICES.md).

## Данные, перезапуск и reset

Обычный `docker compose -p otklik down` сохраняет PostgreSQL, Redis, Kafka, ключи и вложения в named volumes. Повторный запуск применяет миграции и идемпотентный seed, не создавая дубликатов.

Полный demo reset удаляет данные и вложения только явно выбранного Compose-проекта, затем создает volumes и seed заново:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/reset-demo.ps1 -ConfirmDataLoss
```

Это необратимое удаление локального демо-содержимого; `.env` сохраняется. Для изолированной проверки можно указать отдельный `-ProjectName`, `-FrontendPort` и `-ApiPort`.

## Что не входит в MVP

- Передача обращений во внешние государственные или ведомственные сервисы.
- ML-классификация: подсказка категории использует прозрачные настраиваемые правила/маркеры, решение принимает оператор.
- Production SLA, круглосуточное дежурство и организационные регламенты эскалации.
- Реальная эксплуатационная аттестация, внешний аудит, penetration test, backup/restore и сертификация обработки персональных данных.
- Гарантия экстренного реагирования без добровольного контакта: интерфейс честно направляет к экстренным каналам и сохраняет анонимный диалог.
